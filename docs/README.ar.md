# التحكم بوكلاء البرمجة عبر تيليجرام

[English](../README.md)

يشغّل هذا المشروع Codex وClaude Code وغيرهما من الوكلاء على خادم Linux من خلال محادثة تيليجرام خاصة. يمكنك بدء مهمة، ومتابعة تقدمها، وقراءة المخرجات، وإيقافها، ثم متابعة المحادثة نفسها.

واجهة البوت متاحة بالعربية والإنجليزية. يختار البوت العربية تلقائياً عندما تكون لغة حساب تيليجرام عربية، ويحفظ الاختيار لكل مستخدم مسموح له. استخدم `/language ar` للعربية أو `/language en` للإنجليزية في أي وقت. تبقى أسماء الأوامر والوكلاء والمشاريع بالإنجليزية، بينما تقبل التوجيهات والمخرجات النص العربي بالكامل.

## أهم المزايا

- قائمة سماح رقمية لمستخدمي تيليجرام، مع عزل محادثات كل مستخدم.
- تشغيل Codex وClaude Code وأي برنامج سطر أوامر يقرأ من الإدخال القياسي.
- تقدم مباشر، وسجل محفوظ في SQLite، وإمكانية متابعة محادثات الوكيل الأصلية.
- حد لعدد التشغيلات المتزامنة، وتشغيل واحد فقط لكل مجلد مشروع.
- حدود للوقت والمخرجات، وإيقاف لمجموعة عمليات الوكيل كاملة.
- اتصال HTTPS صادر فقط؛ لا يحتاج إلى منفذ وارد أو نطاق عام.
- Python 3.11 أو أحدث، بلا حزم تشغيل خارجية.

## الإعداد السريع على Linux

استخدم حساب Linux مخصصاً وغير جذر، وثبّت وكلاء البرمجة وسجّل الدخول إليهم بالحساب نفسه. تحقق أولاً من `codex --version` أو `claude --version`.

1. أنشئ بوتاً من حساب **@BotFather** الموثق، واحتفظ بالرمز السري بأمان.
2. احصل على رقم مستخدم تيليجرام الخاص بك؛ لا تستخدم اسم المستخدم ولا ترسل رمز البوت إلى أي بوت مساعد.
3. انسخ ملفات الإعداد وعدّلها:

```bash
cd ~/telegram-agent-control
cp .env.example .env
cp config.example.toml config.toml
chmod 600 .env config.toml
nano .env
nano config.toml
```

عيّن `TELEGRAM_BOT_TOKEN` و`TELEGRAM_ALLOWED_USERS`، ثم ضع المسارات المطلقة لمشاريعك في `config.toml`. لا يقرأ البرنامج ملف `.env` تلقائياً؛ يجب أن يحمّله الصدَف أو systemd.

4. تحقق من الإعداد وشغّل البوت:

```bash
set -a
. ./.env
set +a
python3 -m agent_control --check
python3 -m agent_control
```

5. أرسل إلى البوت في محادثة خاصة:

```text
/language ar
/projects
/agents
/new codex myapp اشرح هذا المستودع واقترح أول تحسين
/sessions
/status SESSION_ID
/ask SESSION_ID نفّذ التحسين وشغّل الاختبارات
/stop SESSION_ID
```

استبدل `SESSION_ID` بالمعرّف المكوّن من 12 محرفاً الذي يعيده البوت.

## التشغيل الدائم

انسخ وحدة systemd المرفقة وشغّلها بالحساب الذي يملك تسجيل دخول الوكيل:

```bash
mkdir -p ~/.config/systemd/user
cp deploy/telegram-agent-control.service ~/.config/systemd/user/
systemctl --user daemon-reload
systemctl --user enable --now telegram-agent-control
systemctl --user status telegram-agent-control
journalctl --user -u telegram-agent-control -f
```

## الأمان

- محادثات البوت ليست مشفرة من طرف إلى طرف؛ لا ترسل أسراراً أو مستودعات حساسة عبر تيليجرام.
- يعمل الوكلاء بصلاحيات حساب Linux الذي يشغّل الخدمة. استخدم حساباً محدوداً ومخصصاً.
- أسماء المشاريع في `config.toml` هي مسارات بدء موثوقة وليست عزلاً أمنياً لنظام التشغيل.
- لا تضف خيارات تتجاوز صلاحيات الوكيل لمجرد تشغيل أمر مرفوض.
- لا تشغّل أكثر من نسخة واحدة للبوت نفسه، واحتفظ بنسخة احتياطية من قاعدة SQLite عند الحاجة.

للتفاصيل الكاملة عن إعداد المحولات، وحدود الاعتمادية، واستكشاف الأعطال والتطوير، راجع [الدليل الإنجليزي](../README.md).
